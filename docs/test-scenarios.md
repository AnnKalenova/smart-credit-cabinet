# Тестовые сценарии

## Ручная проверка в интерфейсе

Откройте http://localhost:8080. На странице входа выберите учётку из списка (пароль у всех `demo1234`). У каждой демо-компании свой исход — так за 10–15 минут можно пройти все ветки процесса.

Чтобы сценарии шли «с нуля», поднимайте стенд на чистой базе: `docker compose down -v && docker compose up -d --build`.

### Т1. Автоматическое одобрение и выдача — `smirnov`

1. На главной видно: предварительный лимит экспресс-кредита, обороты по счёту за 12 месяцев, данные компании.
2. «Подобрать кредит» → цель «Закупка товара, сырья, материалов», сумма 3 000 000, срок 12 мес.
   **Ожидаемо:** первым идёт «Оборотный кредит» с отметкой «Подходит лучше всего», ставка 18,5–21%, платёж около 277 тыс. ₽.
3. «Оформить» → черновик. Данные компании, выручка и контакт уже заполнены. Справа — предварительный расчёт.
4. «Подписать согласия» → «Подставить» демо-код → «Подписать» → «Отправить заявку».
   **Ожидаемо:** конвейер переходит на шаг «Проверка и оценка», подшаги меняются в реальном времени: проверка данных → ЕГРЮЛ → ФНС → БКИ → рейтинг → условия.
5. Через 10–15 секунд — «Готово предложение»: 3 000 000 ₽ на 12 мес. под 18,5%, автоматическое решение, блок «Почему такие условия».
6. «Выбрать этот вариант» → «Посмотреть договор и график» → «Подписать кодом».
   **Ожидаемо:** «Деньги на расчётном счёте», номер договора и ссудного счёта. В «Открыть график платежей» — 12 платежей.

### Т2. Встречное предложение — `kuznetsova`

1. «Подобрать кредит» → «Открыть точку или сделать ремонт», 1 000 000 ₽, 12 мес. → «Экспресс-кредит» → «Оформить».
2. Подписать согласия, отправить.
   **Ожидаемо:** «Готово встречное предложение» с двумя вариантами: вся сумма на 24 мес. или около 590 тыс. ₽ на 12 мес. Причина: платежи по всем кредитам не должны превышать 40% поступлений. Видно, что помогло решению и что снизило оценку.
3. Выбрать любой вариант, подписать — кредит выдан.

### Т3. Ручное рассмотрение → одобрение — `lebedev`, затем `analyst`

1. `lebedev`: «Купить оборудование», 25 000 000 ₽, 60 мес. → «Инвестиционный кредит».
2. В черновике: описать залог, приложить два документа («Демо-файл» у счёта поставщика и у отчётности), подписать согласия, отправить.
   **Ожидаемо:** статус «У кредитного специалиста», срок решения — через 4 часа.
3. `analyst`: заявка во вкладке «Ручное рассмотрение», причина — «Сумма выше лимита автоматического решения (15 млн ₽)». В досье: скоринг 815 баллов, рейтинг A, факторы с баллами, сведения ЕГРЮЛ/ФНС/БКИ, расчёт лимита и ставки.
4. «Взять в работу» → «Одобрить»: условия подставлены из рекомендации системы → «Отправить предложение».
5. `lebedev`: «Готово предложение», решение кредитного специалиста. Подписать — кредит выдан.

### Т4. Повышенный риск, запрос документов — `nikitin`, затем `analyst`

1. `nikitin`: «Исполнить контракт или тендер», 8 000 000 ₽, 18 мес. → «Оборотный кредит», приложить контракт с заказчиком, отправить.
   **Ожидаемо:** ручное рассмотрение. Триггеры: рейтинг D, налоговый долг 420 тыс. ₽, смена руководителя 2 месяца назад.
2. `analyst`: «Запросить» → отметить документ, задать вопрос клиенту → «Отправить запрос».
3. `nikitin`: «Банку нужны уточнения» → приложить документ, ответить → заявка снова проходит конвейер и возвращается специалисту.
4. `analyst`: «Одобрить» с меньшей суммой (например, 5 000 000) и сообщением клиенту → у клиента встречное предложение.

### Т5. Автоматический отказ — `fedorov`

Экспресс-кредит 2 000 000 ₽ на 24 мес. **Ожидаемо:** отказ за несколько секунд. Причина: компания в стадии ликвидации по данным ЕГРЮЛ. Доступна кнопка «Подать новую заявку с этими данными».

### Т6. Запрос уточнений → одобрение — `morozov`

1. «Закрыть кассовый разрыв», 350 000 ₽ → «Овердрафт». В черновике указать выручку 14 400 000 ₽ (по оборотам на счёте подставлено около 7,8 млн).
2. Отправить. **Ожидаемо:** «Нужны уточнения» — выручка в 1,9 раза больше поступлений; банк просит выписку из другого банка и пояснение.
3. Приложить выписку («Демо-файл»), написать пояснение, «Отправить ответ».
   **Ожидаемо:** заявка снова проходит конвейер, одобрен лимит 350 000 ₽.

### Т7. Права подписи — `orlova`, затем `smirnov`

1. `orlova` (главный бухгалтер): создать заявку и заполнить её. Вместо «Подписать согласия» — подсказка, кто может подписать, и кнопка «Передать на подпись».
2. `smirnov`: в колокольчике уведомление «Нужна ваша подпись». Открыть заявку, подписать согласия, отправить.
3. Когда готово предложение, `orlova` видит условия, но выбрать вариант, отказаться или подписать договор не может — только «Передать на подпись». Свой черновик бухгалтер может отменить, отправленную заявку отзывает руководитель.

### Т8. Отказоустойчивость — `analyst` и любой клиент

1. `analyst` → «Мониторинг» → «Бюро кредитных историй» → «Отключить» (на 2 минуты).
2. Клиент отправляет заявку.
   **Ожидаемо:** на шаге сбора данных подшаг «Бюро кредитных историй временно не отвечает — повторим запрос через 2 с (попытка 2 из 5)». Паузы между попытками растут: 2, 4, 8, 16 с.
3. Вариант А: вернуть сервис («Восстановить») до исчерпания попыток — заявка продолжит движение сама.
   Вариант Б: дождаться исчерпания попыток — заявка уйдёт аналитику с причиной «внешний источник недоступен». Аналитик восстанавливает сервис и нажимает «Повторить проверку».
4. В досье, вкладка «Журнал» — все попытки вызова с ошибками и длительностью. На дашборде — ошибки по сервису.

### Т9. Ключевая ставка — `risk`

«Параметры политики» → изменить ключевую ставку (например, на 15) → «Сохранить». Новые предложения и подбор продукта считаются по новой ставке. В расшифровке ставки — новая ключевая.

### Т10. Безопасность и ограничения

| Проверка | Ожидаемо |
|---|---|
| Запросить чужую заявку по API под другим клиентом | 404 «Заявка не найдена» |
| Бухгалтер вызывает `POST /submit` или `/sign` | 403 с объяснением, кто может подписывать |
| Ввести неверный код подписи | «Неверный код подтверждения»; после 5 попыток — нужен новый код |
| 10 раз подряд ввести неверный пароль | 11-я попытка — «Слишком много неудачных попыток входа. Попробуйте через 10 минут» (429), другие логины входят как обычно |
| Загрузить файл `.pdf`, который на самом деле не PDF (например, переименованный `.exe`) | «Содержимое файла не соответствует его формату» |
| Загрузить файл больше 10 МБ | интерфейс сразу сообщает о лимите; API отвечает 413 |
| Подписать договор после даты «Действует до» в предложении | 409, заявка переходит в «Срок предложения истёк», доступна повторная подача |
| Отправить в API сумму `1e30`, строку вместо числа или пустую сумму в черновике | 422 со списком понятных ошибок: «Сумма: должно быть не больше 10 000 000 000» |
| Отправить черновик без согласий или документов | список того, что нужно сделать, без перехода статуса |
| Клиент заходит в `/b/...`, аналитик — в `/c/...` | перенаправление в свой раздел; API возвращает 403 |
| Изменить ставку под аналитиком | 403: менять параметры может только риск-менеджер |
