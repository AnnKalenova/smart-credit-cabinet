# Подготовка к отбору

## Проверенная версия

- [ ] Собрать фронтенд и пройти проверки CI.
- [ ] Проверить локальный запуск через Docker по README.
- [ ] Пройти автоматическую выдачу, встречное предложение, запрос уточнений и решение специалиста.
- [ ] Убедиться, что ошибка сохранения не теряет введённую сумму при переходе, нажатии «Назад» и выходе.
- [ ] Создать новый тег, например `v1.1.1`, на проверенном коммите. Старый `v1.1.0` не перемещать.
- [ ] Сохранить полный hash (`git rev-parse HEAD`) и передать его вместе с тегом в заявке на отбор.
- [ ] Убедиться, что онлайн-демо собрано из того же коммита.

## Онлайн-демо

- [ ] Открыть сайт и проверить вход предпринимателя и специалиста.
- [ ] Перед демонстрацией проверить, что демо-компании не исчерпали лимиты из-за прошлых прогонов.
- [ ] При необходимости сбросить именно демонстрационные данные через `deploy/reset-demo.sh`.

Сброс удаляет все заявки, кредиты и изменения политики на этом стенде. Он не нужен для обычного
обновления приложения. Сначала убедитесь, что эти данные не требуется сохранять. Домен, секреты и
том сертификатов этот скрипт не удаляет. Не используйте для обновления `docker compose down -v`.

## Проверка пользовательской пользы

Исследование пока содержит гипотезы, а не подтверждённые результаты. До демонстрации полезно
провести 3–5 пробных прохождений с людьми, которые не знакомы с интерфейсом:

1. Попросить подобрать кредит под конкретную задачу и объяснить стоимость.
2. Попросить разобраться во встречном предложении и выбрать условия.
3. Попросить передать подготовленную бухгалтером заявку руководителю.
4. Измерить время выполнения, записать ошибки и места, где понадобилась подсказка.
5. Зафиксировать, какие изменения внесены после наблюдений.

Добавляйте в `docs/research.md` только реально полученные результаты, с датой, количеством
участников и ограничениями проверки. Не выдавайте результаты синтетических сценариев за
доказанный рост конверсии или экономию банка.

## Вопрос к организаторам

На странице 7 PDF упоминается изменение новостной ленты под клиента. Роль этой функции в
кредитном процессе не раскрыта. До уточнения не считайте уведомления по заявке подтверждённой
заменой этого требования. Зафиксируйте ответ организаторов и при необходимости дополните MVP.
