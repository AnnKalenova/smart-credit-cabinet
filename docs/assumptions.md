# Допущения и смоделированные части

Кейс разрешает упрощения, если они явно описаны и сохраняют смысл процесса (стр. 11, п. 06). Здесь собраны все допущения решения: что смоделировано, что упрощено и на каких данных проверяется.

## Смоделированные интеграции

| Что | Как сейчас | Как было бы в банке |
|---|---|---|
| ЕГРЮЛ / ЕГРИП | `integrations-mock`: `GET /egrul/v1/entities/{inn}`, выписка из синтетических данных | СМЭВ / сервисы ФНС |
| ФНС «Прозрачный бизнес» | `GET /fns/v1/transparent-business/{inn}` — выручка, прибыль, налоговый долг, признаки риска | API ФНС или агрегатор данных о контрагентах |
| Бюро кредитных историй | `POST /bki/v1/credit-reports` — требует ID подписанного согласия | один или несколько БКИ по 218-ФЗ |
| АБС банка | `POST /abs/v1/loans` — открывает ссудный счёт и «зачисляет» деньги, идемпотентно | АБС через шину предприятия |
| Электронная подпись | одноразовый код внутри кабинета; в демо-режиме код показывается в окне подписи. Вне демо-режима код должен доставлять канал банка, в этой сборке он не подключён | подпись в интернет-банке, УКЭП или Госключ |
| Вход | логин и пароль демо-учёток (создаются только в демо-режиме) | SSO интернет-банка (OIDC) |
| Хранилище документов | том Docker `uploads` | S3-совместимое хранилище |

Контракты упрощены, но смысл интеграций сохранён: источники вызываются по ИНН, отчёт БКИ запрашивается только с согласием, у вызовов есть таймауты, повторы, журнал и корреляционный ID, выдача идемпотентна. Симулятор умеет «падать» и «тормозить» по команде — так проверяется отказоустойчивость.

## Демо-режим

Стенд по умолчанию работает в демо-режиме (`DEMO_MODE=true`), чтобы сценарии можно было пройти без своих данных и без SMS:

| Что | В демо-режиме | При `DEMO_MODE=false` |
|---|---|---|
| Демо-учётки | создаются при первом запуске, выбираются на странице входа одной кнопкой | не создаются; учётки с логином из демо-данных и общеизвестным паролем `demo1234` отключаются при старте API и снова включаются при возврате в демо-режим. Учётку с тем же логином, но своим паролем это не затрагивает. Список учёток — 404. Пользователи в рабочей версии приходят через SSO банка |
| Код подписи | показывается в окне подписи, кнопка «Вставить код» | не возвращается: его должен доставлять канал банка (в этой сборке не подключён) |
| Примеры документов | кнопка «Пример файла» рядом с «Загрузить файл» | кнопки нет, API — 404 |
| Моделирование сбоев | «Мониторинг» → «Отключить» / «Замедлить» / «Восстановить» | недоступно, API — 404 |
| Секрет подписи токенов | можно оставить значение по умолчанию | API не стартует, пока не задан свой `JWT_SECRET` |

## Упрощения процесса

- **Клиенты** — только действующие клиенты банка: ИП и юрлица. Данные о них (реквизиты, руководитель, обороты по счёту) банк уже знает, поэтому в заявке они подставляются автоматически.
- **Продукты** — четыре собственных продукта (экспресс, оборотный, инвестиционный, овердрафт), к реальной линейке Альфа-Банка не привязаны. Ставки считаются от ключевой ставки Банка России (по умолчанию 14%, меняется в интерфейсе риск-менеджера).
- **Скоринг** — детерминированная балльная модель вместо обученной. Причина: нет исторических данных о дефолтах, а логика должна быть прозрачной. Замена на статистическую модель описана в [decision-logic.md](decision-logic.md).
- **Залог** — описывается текстом в заявке. Оценки залога, страхования и регистрации обременения нет.
- **Поручительство** — отметка в заявке: снижает ставку и добавляет условие в предложение, отдельного договора поручительства нет.
- **Документы** — принимаются файлы любых допустимых форматов, до 20 на заявку. Содержимое не распознаётся: факт загрузки нужного типа документа считается достаточным (в банке здесь было бы распознавание и проверка специалистом). Для проверки без своих файлов в демо-режиме есть кнопка «Пример файла». При повторной подаче документы переносятся в новую заявку ссылкой на тот же файл, без копирования.
- **Подтверждение выручки** — выписка из другого банка учитывается с дисконтом 20% без разбора её содержимого и не больше чем вдвое выше поступлений на счёт. Если по выписке выходит больше, заявку проверяет специалист.
- **Конструктор условий** — считает решение на сведениях ЕГРЮЛ, ФНС и БКИ, полученных при рассмотрении исходной заявки, и ничего не сохраняет. Новая заявка на выбранных условиях запрашивает сведения заново, поэтому её решение совпадает с подсказкой, если данные за это время не изменились.
- **Полномочия** — упрощённая модель «может подписывать / не может». Доверенности с перечнем полномочий и сроками не моделируются.
- **График платежей** — аннуитет без учёта праздников и переносов. По овердрафту — пример при полном использовании лимита.
- **Комиссии и полная стоимость кредита** — не считаются, переплата показывается как сумма процентов.
- **Выдача** — мгновенная, без проверки комплаенса (115-ФЗ) и лимитов банка. Если АБС не отвечает, выдача повторяется автоматически до 30 раз, затем её повторяет специалист.
- **SLA ручного рассмотрения** — 4 часа календарного времени, без учёта рабочего календаря.
- **Уведомления** — только внутри кабинета. Почта, SMS и мессенджеры не участвуют в сценарии (стр. 11, п. 05).
- **Оформление** — интерфейс в духе цифровых продуктов Альфа-Банка: палитра, скругления и типографика опираются на открытые дизайн-токены библиотеки core-components (MIT), шрифт Golos Text. Логотип и товарные знаки банка не используются — подробнее в [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md).

## Синтетические данные

- 6 демо-компаний и 9 пользователей описаны в `data/synthetic/companies.json`. Файл создаёт генератор `tools/generate_synthetic_data.py`.
- ИНН и ОГРН имеют корректные контрольные цифры, но начинаются с несуществующего кода «0000». Совпадение с реальными компаниями исключено.
- Даты заданы относительно текущего дня («N месяцев назад»), обороты по счёту генерируются с фиксированным seed. Сценарии ведут себя одинаково в любой день проверки.
- Имена людей, названия компаний, банков-кредиторов и адреса вымышлены.

## Правовые аспекты

В решении уже заложены основные требования, которые понадобятся в рабочей версии:

- согласие на запрос кредитной истории (218-ФЗ) и обработку персональных данных (152-ФЗ) подписывается до запроса в БКИ и хранится с автором и временем;
- решение по заявке объяснимо: сохраняются причины, факторы, версии модели и политики;
- ИИ в принятии кредитного решения не используется. Решение принимают правила и, при необходимости, человек.
